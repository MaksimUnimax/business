# Контекст проекта для восстановления диалога

## Назначение документа

Этот документ нужен, чтобы при обрыве чата, смене ИИ или смене исполнителя можно было быстро восстановить состояние проекта и продолжить с правильного места.

Этот документ нужно обновлять после каждого важного этапа.

## Проект

Проект: база профессий, специальностей, услуг и направлений для будущей автоматической подготовки бизнес-планов.

Один из режимов будущей системы — бизнес-план под соцконтракт.

Соцконтракт не является единственным режимом. Система должна также поддерживать обычный бизнес-план с другим бюджетом.

## Главные решения

1. Сейчас не делаем вопросы, подбор и рекомендации.
2. Сначала строим базу профессий, специальностей и направлений.
3. Потом готовим документы для разработки.
4. Только потом продолжаем разработку продукта.
5. Система не должна придумывать профессии и направления из головы.
6. Финансовая аналитика и бизнес-планы должны строиться по проверенным источникам.
7. Бюджет клиента должен поддерживать точную сумму, верхнюю границу, диапазон и неизвестный бюджет.
8. Соцконтракт — отдельный режим, но не единственный.
9. ИИ и инструменты должны быть заменяемыми.
10. В клиентском продукте ручной человек не должен быть обязательной частью процесса.

## Бюджет клиента

Будущая система должна поддерживать ввод бюджета:

1. точной суммой: например, `1 200 000 рублей`;
2. верхней границей: например, `до 3 000 000 рублей`;
3. диапазоном: например, `от 500 000 до 1 500 000 рублей`;
4. неизвестным бюджетом.

Бюджет должен использоваться для выбора подходящих направлений и для подготовки бизнес-плана.

## ИИ и инструменты

Система не должна быть жёстко привязана к Codex, MiMo, DeepSeek или любому другому названию.

Должны быть роли:

1. сборщик информации;
2. аналитик;
3. составитель бизнес-плана;
4. проверяющий;
5. собеседник с клиентом.

Каждая роль должна быть заменяемой.

Каждая роль может работать:

1. через командную строку;
2. через API.

Текущий черновой вариант:

1. Codex + браузер может собирать информацию по ссылкам;
2. MiMo может делать анализ;
3. позже любой из этих исполнителей может быть заменён.

## Источники и факты

Все факты должны хранить источник.

Факты и выводы должны храниться отдельно.

Если данных не хватает, система должна писать:

`недостаточно данных`

а не придумывать.

## Цены

Цены оборудования и услуг меняются.

Каждая цена должна иметь:

1. источник;
2. ссылку;
3. дату сбора;
4. город или регион;
5. срок актуальности;
6. дату следующего обновления.
